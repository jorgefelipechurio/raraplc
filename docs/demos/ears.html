Claude · EARS proposal a few seconds ago

When DI_limit_x becomes ACTIVE, the system shall stop stepper_axis_x immediately (speed to 0).

Specification auditor · HAZOP just now

Step 1 (linter): no broken references, no contradictions. Step 2 (HAZOP, guide word NO): what happens if DI_limit_x is faulted or has no valid signal when the axis is enabled?

medium severity

If DI_limit_x does not report a valid state when stepper_axis_x is enabled, then the system shall keep stepper_axis_x disabled and report an interlock fault.

Compiled to block just now 
auditor:
  id: aud_extruder_axis_x
  target_output: do_stepper_axis_x
  interlock_rules:
    - description: "limit switch active"
      condition: "DI_limit_x == ACTIVE"
      action: "force_output(0)"
    - description: "limit switch has no valid signal at enable"
      condition: "DI_limit_x == INVALID"
      action: "disable_output() ; report_fault('interlock')"

public-docs / hardware / stepper-axes.md Stepper motor axes — supported interfaces

On the main board, any low-end output can drive the STEP/DIR inputs of an external stepper driver module (open loop, ~60 ns switching, so the driver sets the speed limit, not the PLC). Closed-loop axes with encoder feedback are stage 2: the RARA.MB motion HAT.

public-docs / blocks / limit-switch-interlocks.md Limit switch as interlock — recommended EARS pattern

The standard pattern is event-driven ("When DI_x becomes ACTIVE…"), never a polled condition — this way the runtime auditor treats it as a hardware interlock, with the same priority as a door or an overtravel limit.

public-docs / firmware / lowend-axis-wiring.md Low-end outputs and fast inputs for an axis

Use two low-end outputs for STEP and DIR (a third for ENABLE if the driver has one). Any digital input can be the limit switch; set its firmware filter to 0 ms if it also reads an encoder.
